# DevOps-стенд: автоматический деплой Go-приложения с Ansible, Docker и Prometheus

Практический DevOps-проект, который показывает, как построить небольшую распределённую инфраструктуру с нуля: создать виртуальные серверы, подготовить их через Ansible, развернуть контейнеризированное Go-приложение и подключить мониторинг Prometheus + Grafana.

Проект можно использовать как **готовый лабораторный стенд для изучения DevOps, Infrastructure as Code, Docker, Ansible, мониторинга и автоматизации деплоя**.

---

## 🎯 Что вы получите, изучив проект

Этот репозиторий полезен тем, кто хочет не просто прочитать о DevOps-инструментах, а увидеть, **как они работают вместе в единой инфраструктуре**.

На практике можно изучить:

* как автоматизировать настройку серверов с помощью **Ansible**;
* как запускать приложение в **Docker-контейнере**;
* как разделить приложение и систему мониторинга на разные узлы;
* как собирать метрики приложения с помощью **Prometheus**;
* как визуализировать состояние системы через **Grafana**;
* как организовать взаимодействие нескольких серверов;
* как передавать Docker-образы без Docker Registry;
* как реализовать **air-gapped deployment** через `.tar`-архивы;
* как использовать **Multipass** для создания локальной виртуальной инфраструктуры;
* как автоматизировать повторяемое развёртывание инфраструктуры.

В результате репозиторий даёт возможность увидеть **полный DevOps workflow: от виртуальной машины до работающего приложения с мониторингом**.

---

## 💡 Для кого этот проект

Проект будет полезен:

### Начинающим DevOps-инженерам

Можно использовать репозиторий как практическую лабораторную работу для знакомства с:

**Linux → Docker → Ansible → IaC → мониторинг → автоматизация деплоя.**

### Разработчикам Go

Проект показывает, как подготовить Go-приложение к контейнеризации и добавить в него экспорт метрик для Prometheus.

### Тем, кто изучает Infrastructure as Code

Ansible используется для автоматической подготовки и настройки серверов вместо ручного выполнения одних и тех же команд.

### Тем, кто изучает мониторинг

Prometheus собирает метрики приложения, а Grafana позволяет представить их в удобном для анализа виде.

### Для портфолио

Репозиторий демонстрирует не отдельный Dockerfile или Ansible playbook, а **связку нескольких DevOps-инструментов в единой инфраструктуре**.

# 🏗 Архитектура

Инфраструктура состоит из нескольких независимых Ubuntu-узлов, созданных с помощью Multipass.

```text
                         ┌─────────────────────┐
                         │   Control Node      │
                         │      Ansible        │
                         └──────────┬──────────┘
                                    │
                          SSH / Ansible
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
                    ▼                               ▼
        ┌─────────────────────┐         ┌─────────────────────┐
        │     App Server      │         │   Monitor Server    │
        │                     │         │                     │
        │   Docker            │         │   Prometheus        │
        │   Go Application    │◄────────│   Grafana            │
        │   Metrics           │ metrics │                     │
        └─────────────────────┘         └─────────────────────┘
```

### Узлы инфраструктуры

| Узел           | Назначение                               |
| -------------- | ---------------------------------------- |
| Control Node   | управление инфраструктурой через Ansible |
| App Server     | запуск Go-приложения в Docker            |
| Monitor Server | Prometheus + Grafana                     |

> IP-адреса узлов задаются в `ansible/inventory.ini` и могут отличаться в вашей среде.

# 🔄 Как работает проект

Процесс развёртывания состоит из нескольких этапов.

### 1. Создание инфраструктуры

Multipass создаёт отдельные виртуальные машины Ubuntu.

```text
Multipass
   │
   ├── Control Node
   ├── App Server
   └── Monitor Server
```

### 2. Подготовка серверов

Ansible подключается к узлам по SSH и автоматически выполняет необходимые операции по настройке инфраструктуры.

Например:

```bash
ansible-playbook -i ansible/inventory.ini ansible/setup_nodes.yml
```

Это позволяет отказаться от ручной настройки каждого сервера.

### 3. Сборка приложения

Go-приложение собирается в Docker-образ с использованием multi-stage Dockerfile.

Это позволяет отделить этап сборки от конечного runtime-образа.

### 4. Подготовка Docker-образов

Вместо обязательного использования внешнего Docker Registry образы можно сохранить в архивы:

```text
app.tar
prometheus.tar
grafana.tar
```

### 5. Передача образов

Ansible передаёт подготовленные образы на необходимые серверы.

Такой подход позволяет организовать деплой даже в среде с ограниченным или отсутствующим доступом к внешним registry.

### 6. Запуск сервисов

На App Server запускается Go-приложение.

На Monitor Server запускаются:

```text
Prometheus
Grafana
```

### 7. Сбор метрик

Go-приложение предоставляет метрики, которые получает Prometheus.

```text
Go Application
       │
       │ metrics
       ▼
   Prometheus
       │
       ▼
    Grafana
```

В результате можно не только запустить приложение, но и наблюдать за его состоянием.

После запуска можно проверить доступность сервисов.

### Grafana

```text
http://localhost:3000
```

### Go-приложение

```text
http://localhost/
```

# ☁️ Запуск распределённой инфраструктуры

## 1. Создание виртуальных машин

Пример создания узлов:

```bash
multipass launch --name control --cpus 1 --memory 1G
multipass launch --name app-server --cpus 1 --memory 1G
multipass launch --name monitor-server --cpus 1 --memory 1G
```

Проверить созданные машины:

```bash
multipass list
```

---

## 2. Настройка SSH

На управляющем узле создайте SSH-ключ:

```bash
ssh-keygen -t rsa -b 4096 -N "" -f ~/.ssh/id_rsa
```

После этого добавьте публичный ключ на необходимые серверы.

---

## 3. Проверка Ansible

Перед деплоем рекомендуется проверить доступность всех узлов:

```bash
ansible all -i ansible/inventory.ini -m ping
```

Если серверы отвечают, инфраструктура готова к автоматизированной настройке.

---

# 🐳 Установка Docker

Запустите Ansible playbook:

```bash
ansible-playbook -i ansible/inventory.ini ansible/setup_nodes.yml
```

Playbook автоматически подготавливает узлы для дальнейшего запуска контейнеров.

---

# 🚢 Деплой приложения

Основной deployment выполняется через:

```bash
ansible-playbook -i ansible/inventory.ini ansible/deploy.yml -K
```

или:

```bash
ansible-playbook -i ansible/inventory.ini ansible/deploy.yml --ask-become-pass
```

Ansible выполняет необходимые действия для передачи образов, настройки Docker и запуска сервисов.


### Grafana


```text

```

# 🔐 Air-gapped deployment

Одна из практических особенностей проекта — возможность передавать Docker-образы без обращения к внешнему Docker Registry.

Схема выглядит так:

```text
Docker build
     │
     ▼
Docker image
     │
     ▼
   .tar
     │
     │ SSH / Ansible
     ▼
Удалённый сервер
     │
     ▼
Docker load
     │
     ▼
Запуск контейнера
```

Такой подход полезен для понимания принципов развёртывания в изолированных или ограниченных сетевых средах.
